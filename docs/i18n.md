# Internationalization

## Locale selection

All configured locales share the same URLs through Nuxt i18n's `no_prefix` strategy. The supported locales and `defaultLocale` are declared in [nuxt.config.ts](../nuxt.config.ts). The same locale selection applies on an initial load of any page.

1. Use the locale stored in `i18n_redirected` if it is supported.
2. Otherwise, match the browser's preferred languages using the `Accept-Language` header during SSR.
3. Use `defaultLocale` if no supported language matches.

Client-side navigation keeps the active locale. Use Nuxt i18n's `setLocale()` for an explicit language change. It updates the cookie and the rendered language while keeping the current URL.

## Messages and metadata

Locale messages live in [i18n/locales](../i18n/locales). The [application shell](../app/app.vue) uses the active locale for the document's `lang`, default title and description.

## Add a selectable language

1. Create a JSON file in [i18n/locales](../i18n/locales). Use the message keys from the `defaultLocale` file and translate their values, preserving any interpolation placeholders.
2. Add an entry to `i18n.locales` in [nuxt.config.ts](../nuxt.config.ts) with these fields.
   - `code` is the unique identifier stored in the cookie and passed to `setLocale()`.
   - `language` is the BCP 47 language tag used for browser-language matching.
   - `name` is the label shown in the selector. Use the name as it is written in that language.
   - `file` is the new JSON filename relative to `i18n/locales`.
3. Test the new language using a browser session with an empty locale cookie and the new language at the top of its preferences. Check that the page text and metadata use the expected language.

For the [Phase 6 language selector](roadmap/roadmap.md#phase-6), use `locales` from `useI18n()` to populate the options. Display each locale's `name` and call `setLocale(code)` when selected. The configured list then determines which languages are selectable.
